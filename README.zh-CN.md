# Path of Idle In-Game Search

[English](README.md) · [한국어](README.ko.md) · **简体中文** · [繁體中文](README.zh-TW.md)

一款非官方 Windows 模组，可在 Path of Idle 游戏内搜索和管理背包、Warehouse 与 Vault 中的物品。它通过一个不透明的覆盖窗口提供搜索、完整提示、游戏原生物品移动、按品质批量开启以及 0.1×–100× 速度控制。

## 功能

- 使用 `F3` 或 `Ctrl+F` 打开或关闭窗口
- 按名称、品质、部位、等级、词缀、套装和存放位置搜索
- 空格表示 `AND`，`|` 表示 OR，`-词语` 表示排除，`"短语"` 表示完整短语
- 仅显示匹配物品并高亮匹配文字
- 分别查看背包与 Warehouse/Vault 结果
- 多选 Rare、Legendary、Mythic、Set、Unique 和其他品质；再次点击即可取消
- 仅搜索词缀和套装效果
- 悬停查看完整说明、全部词缀、套装部件及各阶段套装效果
- 直接从搜索结果在背包与仓库之间移动物品
- 使用游戏自身的存储逻辑，按已解锁状态和品质规则移入 Warehouse 或 Vault
- 按品质多选批量开启装备箱和符文箱，并支持“及以上”模式
- 可跳过二次确认、在空间不足时只开启可容纳数量，并自动存放新装备
- 通过主要的“装备＋技能自动构筑”同时评估八个装备槽、基础／主动技能组合以及完整的专精与点数等级向量；评估采用有界的原生 60 秒预览
- 从选择到应用与验证都使用同一个构筑方案令牌和精确等级向量；八个槽位的精确物品、已学与装备授予技能、技能变体、保存／有效／上限等级，以及已用／剩余点数必须全部匹配，才会报告成功
- 将整个联合应用作为原子操作处理。若装备移动、转换、重置、分配或最终验证任一步失败，模组会还原原装备与天赋、本次运行消耗的 Blood、天赋进度计数器及已保存的技能偏好；背包已满且没有可逆中转空位时会在提交前安全停止
- 装备过程中遵循游戏原生 Warehouse/Vault 路由，并在成功后将物品规范到已解锁的正确 Vault 分组
- 强制遵守职业与技能武器规则，并使用游戏原生 Mythic 装备数量限制
- 结合游戏原生属性、符文词缀、已激活套装阶段、技能变体和协同，估算约 60 秒持续性能；无法安全表示的运行时条件会拒绝该预览路径，而不是加入猜测值，因此它仍是有界估算，并非包含敌人与战斗 AI 的精确 DPS
- 装备授予的技能会参与性能评分，但不会占用 Shrine 已学技能槽或消耗天赋点
- 可选择自动、物理、元素、火焰、冰霜、闪电、召唤物、流血、腐蚀、暴击、辅助或防御主题；自动主题根据技能的原生伤害类型确定元素方向，不再猜测本地化名称或说明中的关键词
- 可在设定次数内使用 Shrine 的正常付费转换寻找符合性能目标的技能；保留重置费用以及固定／Alien 技能，任何转换、重置或分配验证不完整时都不会报告成功
- 提供高级“仅应用装备”和“仅按当前装备应用技能”恢复工具，以便只需重做一侧时使用；它们不能替代主要的联合优化
- 使用预设按钮或直接输入，将游戏速度调整为 0.1×–100×
- 仅在模组窗口获得焦点时阻止游戏键盘；角色切换滚轮也只在鼠标位于已聚焦窗口内时阻止
- 保存窗口位置、搜索词、筛选、速度、语言及批量开启设置
- 自动跟随游戏语言，或手动选择韩语、英语、简体中文和繁体中文

物品名称和说明使用游戏当前提供的本地化文本，英文物品名也会作为搜索别名加入索引。

## 安装与更新

1. 从 [Releases](../../releases) 下载最新的 `PathOfIdleInGameSearch-*.zip`。
2. 完整解压 ZIP。
3. 关闭 Path of Idle。
4. 双击 `install.bat`。
5. 启动游戏并按 `F3`。

安装程序会自动查找 Steam 游戏目录。若未安装 BepInEx，它只会下载固定的官方 `6.0.0-be.760` IL2CPP x64 版本，并在安装前验证 SHA-256。若已安装 BepInEx，则会继续使用现有安装，仅安装或更新本模组 DLL。

发行版 DLL 不包含本模组的诊断日志或调试符号。全新安装 BepInEx 时，控制台和磁盘日志也默认关闭；已有 BepInEx 则保留其原有日志设置。

覆盖旧版本重新安装不会改写 `BepInEx/config/local.pathofidle.ingame-search.cfg`，因此用户设置会被保留。

## 操作

| 操作 | 按键或按钮 |
| --- | --- |
| 打开或关闭窗口 | `F3` 或 `Ctrl+F` |
| 关闭窗口 | `Esc` 或右上角 `×` |
| 更改界面语言 | 标题栏中的 `AUTO·…`/语言按钮 |
| 分级调整速度 | `−` 和 `+` |
| 输入自定义速度 | 点击速度框，输入 `0.1`–`100`，然后按 Enter 或 `应用` |
| 恢复正常速度 | `1×` |
| 查看完整物品详情 | 将鼠标悬停在结果行上 |
| 切换结果页 | 底部按钮，或在结果区域使用滚轮 |
| 选择并运行自动构筑 | 打开 `AUTO BUILD`，选择主题，然后运行主要的“装备＋技能自动构筑” |

搜索品质和开启品质都支持多选。再次点击已选择的品质即可取消；全部取消后会恢复为“全部”。开启“及以上”后，将从所选品质中最低的一个开始，包含所有更高品质。“其他”不参与品质排序，可单独选择。

`WAREHOUSE` 标签包含普通 Warehouse 的所有页面及已解锁的 Vault 品质组。存放装备时，模组会调用游戏原生的 `QuickMoveItemFromBagToStore`，而不是自行猜测目标位置。

批量开启默认需要点击同一按钮两次。启用“跳过确认”后会立即执行，因此请先检查所选品质、剩余空间和“自动入库”设置。模组每帧只开启一个，并验证游戏是否真实扣除；若未扣除，会立即停止且不重试，以防部分奖励重复。筛选针对你所持有箱子的品质，不会修改随机奖励的品质。

自动构筑作用于游戏中当前选择的英雄。主要操作会把两把武器与其他六个装备槽、基础／主动技能组合，以及要保存的完整专精／点数等级向量作为同一个方案联合搜索；当前装备也始终保留在候选中。职业与技能武器规则、已解锁的 Shrine 行、固定与 Alien 技能、包含里程碑的点数预算、游戏原生 Mythic 上限及存储路由都会作为约束。装备授予的技能以授予等级参与性能预览，但不会占用 Shrine 已学技能槽或消耗天赋点。

每个联合候选都会通过约 60 秒的有界原生预览进行比较。预览会读取原生属性、所有运行时词缀、符文、装备授予技能、技能变体、真实的 2 件／4 件套装效果、伤害类型、冷却和技能速度。自动主题直接读取技能的原生伤害类型，而不是根据翻译文本猜测。若某个运行时触发或条件无法安全表示，该预览路径会直接失败，而不会获得虚构分数。该估算假设资源和持续时间充足，并非包含敌方防御、移动决策、目标模式、复杂触发时序、投射物交互、持续伤害叠层、召唤物行为和战斗 AI 的精确 DPS。

某次测试约 20 秒完成，这只是特定电脑与存档下的观测值，并非优化耗时承诺。背包规模、英雄和技能候选不同，所需时间可能更长。

选定结果会获得一个方案令牌。模组会在装备八个部位、执行已配置的正常 Blood 付费 Shrine 转换与重置、分配点数和最终验证时，持续使用同一个令牌及其精确保存等级向量。最终验证会检查八个槽位的精确物品、已学技能、根据最终装备重新推导的装备授予技能、技能变体、保存／有效／上限等级，以及已用／剩余点数；遇到不支持或不完整的状态时会停止，不会报告成功。整个联合应用是原子操作：装备移动后的任一步失败都会还原原装备与天赋行，退还本次运行消耗的 Blood，恢复天赋进度计数器和已保存的基础技能／技能偏好，并在报告失败前验证恢复结果。执行前仍需再次点击确认。

高级“仅应用装备”和“仅按当前装备应用技能”用于只需重做一侧时的恢复操作。由于它们会固定另一侧，因此结果不等同于主要的联合最优方案。

`100×` 等极高速度可能跳过较短的动画或计时器。完成操作后建议恢复为 `1×`。

## 卸载

关闭游戏并运行 `uninstall.bat`。它只删除本模组 DLL，不会删除 BepInEx、其他模组或用户配置文件。

## 从源码构建

需要 .NET 6 SDK 或更高版本。安装 BepInEx 后运行一次游戏以生成 interop 程序集，关闭游戏，再运行 `scripts\build.ps1`。构建过程只引用本地安装的游戏程序集，仓库中不包含游戏文件。

## 兼容性

- Windows x64
- Steam 版 Path of Idle
- Unity IL2CPP 与 BepInEx 6

若游戏更新改变内部数据结构，模组可能需要同步更新。

本项目是非官方粉丝作品，与 Path of Idle 或 BepInEx 的开发者无关。使用非官方模组前，建议备份重要存档。
